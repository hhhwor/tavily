# 百度 AI 搜索三接口对比与选型报告

> 报告日期：2026-07-28（首轮：2026-07-23；标准版复测：2026-07-28）
> 对比对象：百度搜索、智能搜索生成标准版、智能搜索生成高性能版
> 实测规模：20 个通用 Query，覆盖事实、时效、多跳、长尾、混合及 How-to 场景；标准版另完成一次 20 条全量复测

## 1. 执行摘要

本次对比覆盖以下三个接口：

1. 当前生产候选源：`POST /v2/ai_search/web_search`
2. 智能搜索生成标准版：`POST /v2/ai_search/chat/completions`
3. 智能搜索生成高性能版：`POST /v2/ai_search/web_summary`

综合接口能力、20 条实测、排序指标、延迟、内容长度、答案质量和计费后，建议如下：

- **默认检索链路继续使用 `/web_search + SiliconFlow`。** 它的 nDCG@10 最高，延迟最低，返回内容最充足，并且没有额外的大模型 Token 费用。
- **高性能版适合作为需要“搜索 + 原生答案”的可选路由。** 它的候选集经过 SiliconFlow 后 Recall@10 最高，成本按次固定，但原生百度排序不能替代 SiliconFlow。
- **标准版已确认可以用 ERNIE 4.5 完成 20/20 条原生生成，但仍只适合指定模型、深搜索、自有知识注入、Prompt 模板或安全策略等特殊场景。** 原生答案质量有竞争力，但引用内容明显更短，完整流 P50/P95 达 36.44/56.31 秒，并且模型费用独立计费。
- **三个接口都不能直接省略 SiliconFlow。** 在相同候选集上，SiliconFlow 对 nDCG/Recall 的提升显著且稳定。
- **不建议把三个百度接口作为常驻多源同时调用。** 三源 + SiliconFlow 的 nDCG/Recall 为 `0.890/0.530`，没有优于当前单源 + SiliconFlow 的 `0.892/0.529`，但目录价约从 `¥0.036` 增加到 `¥0.1424/Query`。三源聚合答案本轮为 8.25 分、高性能版为 7.80 分，但差值 `+0.45` 的 95% CI 跨 0，尚不足以推翻成本和检索侧结论。
- **不建议让标准版或高性能版直接替换当前默认检索 Provider。** 推荐按场景分流，而不是全量切换。

推荐架构：

```text
默认 Web/RAG 检索
  /web_search → SiliconFlow → 现有回答器/Agent

需要百度原生联网答案
  /web_summary → 原生答案
               → 引用仍使用 SiliconFlow 校正排序

需要指定模型、内部知识或深搜索
  /chat/completions → SiliconFlow → 引用与事实校验
```

数据完整性说明：

- 2026-07-23 首轮同时间窗口测试中，三个接口的检索与排序均为完整 20 条；当前方案与高性能版答案也为完整 20 条。
- 首轮标准版使用 `deepseek-v4-flash`，原生答案只成功 4 条；第 5 条起模型账户返回 `account_overdue`。
- 2026-07-28 再次探测 `deepseek-v4-flash` 仍返回 `account_overdue`；切换文档示例模型 `ernie-4.5-turbo-32k` 后，标准版完成 20/20 条原生答案和 1/3/5 QPS 探针。
- 复测没有同步重跑当前接口和高性能版。因此复测中的三方检索指标是“新标准版结果 vs 2026-07-23 缓存”的跨时间比较，不能替代首轮同时间窗口 A/B。

### 1.1 2026-07-28 标准版复测结论

复测配置：`ernie-4.5-turbo-32k`、`baidu_search_v2`、`search_mode=required`、关闭深搜索与推理、流式输出、网页 Top-20。

| 维度 | 复测结果 |
|---|---:|
| 原生生成成功率 | **20/20** |
| 引用返回 | 20 条/Query，共 400 条 |
| 首引用 P50 / P95 | 4.400s / 5.498s |
| 首答案 Token P50 / P95 | 4.400s / 5.498s |
| 完整流 P50 / P95 | **36.442s / 56.310s** |
| 答案平均字符数 | 1,567 |
| 总 Token | 212,340 |
| 估算模型费用 | ¥0.2079/20 条，约 ¥0.0104/条，不含超出免费额度后的搜索调用费 |

标准版原生答案与两条现有方案同场盲评：

| 配置 | 总分/10 | Correctness/2 | Completeness/2 | Grounding/2 | Freshness/2 | 胜 |
|---|---:|---:|---:|---:|---:|---:|
| 当前 + SF + 固定回答器 | 7.15 | 1.75 | 1.45 | **1.95** | **1.80** | 1 |
| 高性能版原生答案 | **7.75** | **1.90** | 1.75 | **2.00** | 1.75 | 6 |
| 标准版 ERNIE 原生答案 | 7.45 | 1.70 | **1.85** | 1.65 | 1.65 | **10** |
| 平局 | — | — | — | — | — | 3 |

标准版赢的 Query 更多，但平均总分低于高性能版，表示它有较多小幅胜出，同时存在少数较大失分。其 completeness 最好，grounding 和 freshness 较弱。

复测候选在自身相关文档池中，经 SiliconFlow 后 nDCG@10 从 `0.630` 提升至 `0.842`，Recall@10 从 `0.484` 提升至 `0.557`；20 条中 SF 胜 17、平 1、负 2。保留 SiliconFlow 的结论没有变化。

QPS 短突发结果：

| 目标发送速率 | 成功 |
|---:|---:|
| 1 QPS | 4/4 |
| 3 QPS | 4/4 |
| 5 QPS | 4/4 |

12 个 QPS 探针请求的单请求耗时范围为 5.52–21.12 秒。该结果证明服务接受短时 5 QPS 发送，不代表长期 5 QPS SLA。

复测后的判断：标准版生成链路可用，原生答案也有竞争力，但时延远高于高性能版；仍不适合替换默认检索链路。`deepseek-v4-flash` 与 ERNIE 4.5 在同一 API Key 下分别失败和成功，也说明标准版可用性、延迟和成本必须按具体模型评估。

## 2. 接口定位与能力

| 维度 | 当前百度搜索 | 标准智能搜索生成 | 高性能智能搜索生成 |
|---|---|---|---|
| Endpoint | `/v2/ai_search/web_search` | `/v2/ai_search/chat/completions` | `/v2/ai_search/web_summary` |
| 主要定位 | 纯搜索候选源 | 搜索 + 指定大模型生成 | 搜索 + 内置模型生成 |
| 是否生成答案 | 否 | 是 | 是 |
| 模型控制 | 无 | 指定具体模型 | `thinking` / `auto_thinking` / `non_thinking` |
| 多轮对话 | 否 | 支持 | 支持 |
| 网页 Top-K | 最大 50 | V2 普通模式最大 20 | 最大 50 |
| 深搜索 | 不支持 | 支持，最多 100 条、最多产生 10 次调用 | 当前请求参数未开放 |
| 时间过滤 | 支持 | 支持 | 支持 |
| 站点过滤 | 支持 | 支持，最多 20 个站点 | 支持，最多 100 个站点 |
| 自有知识注入 | 不支持 | `additional_knowledge`，支持优先级 | 当前 API 请求结构未直接开放 |
| Prompt 模板 | 不支持 | 支持 `prompt_template` | 支持 `instruction` |
| 搜索开关 | 固定搜索 | `auto` / `required` / `disabled` | 固定搜索 |
| 安全与画像 | 基础安全 | 安全等级、网页安全、用户画像、领域配置 | 能力较少 |
| JSON Schema 输出 | 不支持 | 文档定义为文本/富文本 | 支持 |
| 百度相关性分 | 不返回 | 不返回 | `rerank_score` |
| 百度权威性分 | 不返回 | 不返回 | `authority_score` |
| 引用内容 | 较长摘要/内容 | 文档定义为 200 字以内片段 | 摘要；文档描述可返回全文 |
| Token usage | 无 | 返回 | 不按 Token 计费 |

标准版的优势主要是可配置性，而不是检索质量；高性能版的优势主要是集成简单、成本固定和候选数量较高。

### 3.3 评估口径

- 三个接口的 URL 去重并集作为相关性标注池。
- 相关性由同一个 LLM judge 按 0–3 分标注。
- 排序指标统一计算 nDCG@10、Recall@10、Precision@10、MRR。
- 每个候选源同时评估接口原始顺序和 SiliconFlow 重排结果。
- 答案评估使用交替/确定性盲化位置，评价 correctness、completeness、grounding、freshness。
- 配对差异使用 Query 级 bootstrap 95% 置信区间。

以下指标使用三个接口 URL 并集作为 Recall 分母，属于 2026-07-23 首轮同时间窗口结果。标准版复测的跨时间结果仅用于补充，不覆盖本节。

### 4.1 候选源差异

- 标准版与高性能版 URL Jaccard 均值：`0.965`
- 标准版与当前接口 URL Jaccard 均值：`0.828`
- 标准版 + SF 相比当前 + SF：
  - nDCG 差值：`-0.008`
  - 95% CI：`[-0.104, 0.098]`
  - Recall 差值：`+0.009`
  - 95% CI：`[-0.043, 0.071]`

结论：标准版没有提供新的显著召回或排序收益，绝大多数 Query 与高性能版使用相同或高度相似的候选集。

### 4.2 SiliconFlow 的贡献

在标准版相同候选集上：

| 排序 | nDCG@10 | Recall@10 | P@10 | MRR |

| 标准版 + SiliconFlow | **0.909** | **0.626** | **0.900** | **0.967** |

- nDCG 提升：`+0.177`
- Query 级 95% CI 对应的 SF 优势不跨 0。
- 20 条中 SiliconFlow 胜 18、平 1、负 1。

在高性能版相同候选集上：

| 排序 | nDCG@10 | Recall@10 |
|---|---:|---:|
| 百度 `rerank_score` | 0.733 | 0.547 |
| SiliconFlow | **0.916** | **0.619** |

- nDCG 提升：`+0.183`，95% CI `[0.110, 0.255]`

- Top-10 重合率：`0.555`

结论：百度返回 `rerank_score` 不能替代 SiliconFlow。

#### 4.3.5 聚合建议

- **默认质量路径：继续当前 `/web_search + SiliconFlow`。** 在本样本中 nDCG 最高且成本最低。
- **不常驻三路并发。** 三源目录价约为当前单源的 3.96 倍，质量没有显著提升。
- **需要候选全覆盖时，只考虑“当前 + 高性能”。** 它已覆盖本判分池全部相关候选；标准版没有额外召回价值。
- **高可用优先采用超时后备或 hedged request，而不是每次双发。** 高性能版适合作为当前接口失败/超时后的后备，同时可利用其原生答案。
- **标准版继续按能力路由。** 仅在指定模型、深搜索和知识注入场景调用，不作为默认聚合源。

## 5. 延迟

| 指标 | P50 | P95 | 样本说明 |
|---|---:|---:|---|
| 当前搜索完成 | **1.116s** | **1.291s** | n=20，仅检索 |
| 高性能版首引用 | 1.380s | 2.031s | n=20 |
| 高性能版首答案 Token | 1.381s | 2.032s | n=20 |
| 高性能版完整流 | 4.952s | 7.743s | n=20 |
| 标准版首引用（首轮 DeepSeek） | 1.536s | 2.399s | n=20 |
| 标准版首答案 Token（首轮 DeepSeek） | 5.466s | 6.297s | n=4 |
| 标准版完整流（首轮 DeepSeek） | 7.667s | 16.875s | n=4 |

说明：

- 标准版时延高度依赖模型。复测 ERNIE 能较早开始输出，但长答案使完整流 P50/P95 达到 36.44/56.31 秒。
- 复测与高性能版并非同日调用，但量级差距较大，仍足以确认标准版 ERNIE 不适合低延迟交互场景。

标准版引用内容被截断到约 200 字，虽然 URL 召回与高性能版基本相同，但提供给外部回答器的证据显著更少。这是标准版 + 统一回答器完整性下降的主要原因。

### 6.1 `enable_full_content`

高性能版测试结果：

- 20/20 个携带 `enable_full_content=true` 的请求返回 HTTP 200。
- 3 个 Query 进行了 true/false 配对。
- 32 个匹配 URL 中，true 返回内容更长的数量为 0。
- 400 条高性能引用中，`content` 全部等于 `snippet`。

结论：本次实测没有观察到 `enable_full_content` 的实际收益。由于该字段没有明确出现在当前高性能版请求参数表中，HTTP 200 不能证明服务端采用了该字段。

### 7.2 三方可用方案对比

本节将原“当前单源 + SF”替换为三源聚合方案。使用 2026-07-23 同时间窗口的三个接口 Top-20 候选，按规范化 URL 去重后使用 SiliconFlow 重排，取前 8 条证据交给 Claude Haiku 固定回答器生成答案：

```text
/web_search + /web_summary + /chat/completions 引用
→ URL 去重
→ SiliconFlow 重排
→ Top-8 证据
→ Claude Haiku 固定回答器
```

标准版原生答案在首轮只成功 4 条，因此第三个方案仍是“标准版候选 + SF + 同一固定回答器”；高性能版使用百度原生答案。本表比较的是三条可部署管线，不是三个接口使用同一模型的纯控制实验。

| 高性能原生答案 | 7.80 | 1.85 | 1.70 | 1.90 | 1.70 |
| 标准版 + SF + 固定回答器 | 6.80 | 1.85 | 1.35 | 1.90 | 1.40 |

胜负：

- 三源聚合：7
- 高性能版：7
- 标准版 + SF：0
- 平：6

配对差异：

- 三源聚合减高性能版：总分 `+0.45`，bootstrap 95% CI `[-0.35, 1.20]`，尚不能证明显著领先。
- 三源聚合减高性能版：completeness `+0.25`，95% CI `[0.00, 0.50]`；grounding `+0.10`，95% CI `[0.00, 0.25]`。
- 三源聚合减标准版 + SF：总分 `+1.45`，95% CI `[0.85, 2.05]`，优势不跨 0。

聚合方案在本轮的 completeness 和 grounding 最好，但该结果不能直接解释为“三源必然优于原当前单源”：本节重新生成了聚合答案并重新执行三方盲评，回答器和裁判又使用同一个 Claude 模型，存在生成波动与自偏好。结合第 4.3 节，三源聚合没有带来显著检索 Top-10 增益，因此其答案质量收益仍需用同一轮四方盲评或线上 A/B 复核。

## 8. QPS 与服务行为

### 8.1 高性能版短突发

| 目标发送速率 | 请求数 | HTTP 200 |
|---:|---:|---:|
| 1 QPS | 4 | 4 |
| 3 QPS | 4 | 4 |
| 5 QPS | 4 | 4 |

5 QPS 下有单请求耗时达到 7.02 秒。该结果只证明接口接受短突发，不代表长期稳定吞吐或正式 SLA。

### 8.2 标准版

首轮 DeepSeek 因 `account_overdue` 未执行 QPS。复测 ERNIE 的 1/3/5 QPS 短突发均为 4/4 成功，HTTP 状态均为 200；单请求最大耗时 21.12 秒。该结果补齐了基本吞吐验证，但仍不能代表持续负载、P99 或账户正式限额。

### 8.3 生产接入风险

标准版发生模型欠费时：

- HTTP 状态仍为 200。
- `references` 仍然正常返回。
- `choices[].content` 为空。
- `usage` 不返回。
- 错误位于 SSE 事件内部。

生产实现不能只检查 HTTP 200 或 `references`，必须同时验证：

1. SSE 内没有业务错误码。
2. 至少存在一个非空答案增量。
3. 最终存在完成状态或 Token usage。
4. 搜索成功、生成失败时需要明确降级为“仅搜索结果”，不能伪装成完整回答。

## 10. 最终选型

### 10.1 默认方案

保留：

```text
/web_search → SiliconFlow → 现有回答器
```

理由：

- nDCG@10 最高。
- 延迟最低。
- 引用内容最长。
- 无额外模型 Token 成本。
- 现有实现和故障处理最成熟。

### 10.2 高性能版

适用：

- 需要一次调用获得联网答案。
- 希望成本固定。
- 能接受约 5 秒 P50 的完整流。
- 不需要指定具体模型或深搜索。

接入建议：

- 只作为可选答案路由。
- 保留 SiliconFlow 对引用重新排序。
- 不依赖 `enable_full_content`。
- 对时效问题和复杂问答先灰度，不全量替换。

### 10.3 标准版

适用：

- 必须指定模型。
- 需要深搜索。
- 需要注入内部知识并设置优先级。
- 需要 Prompt 模板、安全策略、用户画像或领域配置。

接入前置条件：

- 明确生产模型：ERNIE 4.5 已通过 20 条测试，DeepSeek-V4-Flash 当前仍返回 `account_overdue`。
- 按 60 秒级尾延迟设计超时、取消和异步降级策略。
- 将当前短突发扩展为持续 QPS、P99 和 429/5xx 测试。
- 保留并验证 `account_overdue`、空答案和部分 SSE 流的降级。
- 确认 200 字引用是否满足生产回答质量。

### 10.4 决策矩阵

| 场景 | 推荐 |
|---|---|
| 默认 Web 搜索 | 当前 `/web_search + SF` |
| RAG/Agent 证据检索 | 当前 `/web_search + SF` |
| 一次调用返回百度原生答案 | 高性能 `/web_summary` |
| 固定、可预测的搜索生成成本 | 高性能 `/web_summary` |
| 指定模型 | 标准 `/chat/completions` |
| 内部知识 + 公网搜索 | 标准 `/chat/completions` |
| 深搜索 | 标准 `/chat/completions` |
| 百度多源常驻聚合 | 不推荐 |
| 百度检索高可用 | 当前接口主用，高性能版超时后备/按需 hedging |
| 直接取消 SiliconFlow | 不推荐 |
| 全量替换当前 Provider | 不推荐 |

## 11. 限制

- 样本为 20 条，适合初步接入决策，不代表全量线上分布。
- 相关性和答案质量由单一 LLM judge 评估，未进行人工复核。
- 当前接口的完整答案生成延迟未纳入，因此只能比较检索完成时间。
- 标准版 ERNIE 原生答案已有 20 条，但 DeepSeek-V4-Flash 仍只有首轮 4 条有效样本。
- 标准版复测没有同步重跑当前接口与高性能版，三方检索指标存在约 5 天的时间偏差。
- QPS 测试为短突发，不等价于长期吞吐或 SLA。
- 百度文档部分页面对默认 QPS 的表格和 FAQ 描述存在差异，应以账户控制台实际配额为准。
