## 1. 结论先行

Chukonu 不替代 xTrimo，也不承担蛋白质、DNA、RNA、细胞等生命模态的基础建模。它能够为百图的生命科学“操作系统”补上一层当前非常重要的能力：

> 把外部知识、模型推演和实验结果组织成可检索、可核验、可追溯、可继续行动的研发证据。

在联合体系中，适合将各组件定位为：

- **xTrimo**：生命科学计算内核与生物规律推演引擎。
- **高通量实验室**：验证模型预测、生产新数据的物理 I/O。
- **生命科学数据平台**：承载序列、组学、细胞、实验和模型训练数据的数据底座。
- **Chukonu**：连接论文、专利、网页及未来领域数据库的知识 I/O，以及管理证据、反证、覆盖缺口和研究任务的控制平面。

Chukonu 带来的核心价值不是“搜索结果更多”，而是让研发系统能够回答以下问题：

1. 为什么值得研究这个靶点、机制或候选物？
2. 支持和反对当前假设的证据分别是什么？
3. xTrimo 的预测与哪些已知研究一致，在哪些地方属于外推？
4. 当前结论还缺少哪些证据或实验？
5. 下一轮实验最应该消除什么不确定性？
6. 一项研发决策在未来能否还原其数据、模型、论文、专利和实验依据？

## 2. 双方能力边界

### 2.1 百图“操作系统”的主要组成

根据《对话百图生科刘维：给做药的人，造一套操作系统》，这套体系包含四个相互依赖的层次：

1. **生命科学基础模型**：通过 xTrimo 对蛋白质、DNA、RNA、细胞等多种生命模态进行统一表征和跨模态推演。
2. **生物数据底座**：整合公共数据、产业端脱敏数据和自建实验数据，突破单任务、单模态的数据孤岛。
3. **干湿实验闭环**：把模型预测送入湿实验验证，再让实验数据回流模型训练和后续决策。
4. **智能实验设备**：通过高通量、端侧计算和按需触发提高数据生产效率，使实验系统逐步具备主动选择能力。

这里的“操作系统”不是传统计算机操作系统，而是一套覆盖模型、数据、任务编排和物理实验的生命科学研发基础设施。

### 2.2 Chukonu 当前能力

Chukonu 当前公开提供两项能力：

- `search`：完成网页、学术论文和专利的多来源发现，返回结构化证据、来源执行情况、质量缺口和可复用的研究种子。
- `research`：围绕研究目标进行持久化多轮检索、反证搜索、PDF 深读、陈述核验、覆盖评估和停止判断，形成可追溯的研究 dossier。

当前内部链路为：

```text
研究问题
  → 查询理解与来源规划
  → 网页/论文/专利并发召回
  → 分领域重排
  → 证据装配与来源标注
  → 多轮扩展及反证检索
  → 陈述核验与覆盖评估
  → 研究档案和停止原因
```

Chukonu 当前处理的是**文档、陈述和证据**，尚不处理生物序列、分子结构、细胞扰动、实验样本或仪器任务。因此，它属于知识研究基础设施，不是生命科学基础模型，也不是实验自动化平台。

## 3. Chukonu 能带来的六类价值

### 3.1 为 xTrimo 提供持续更新的外部知识入口

基础模型参数记录的是训练时吸收的规律，但药物研发所需的外部信息持续变化，包括：

- 新发表的论文、预印本和会议结果；
- 新公开的专利、同族专利和申请人布局；
- 临床试验进展、失败结果和安全性信号；
- 靶点、通路、疾病机制和生物标志物的新解释；
- 竞争对手的管线、合作、授权和终止信息；
- 监管机构发布的指南、审评信息和风险提示。

Chukonu 可以把这些动态信息作为 xTrimo 之外的外部知识层。模型不需要为了每项新知识立即重新训练，也能在任务执行时获得有时间边界、来源边界和许可边界的最新证据。

由此形成的分工是：

- xTrimo 负责从生命原生数据中学习和推演规律；
- Chukonu 负责发现当前世界已经公开了什么，以及这些信息是否足以支持一项具体判断。

### 3.2 为模型预测建立证据上下文

xTrimo 的价值在于发现人类尚未明确总结的规律，但研发决策不能只保留一个预测分数。进入实验或项目立项前，还需要明确：

- 预测是否与已有机制研究一致；
- 是否存在重复失败或相反结果；
- 支持证据来自原始研究、综述、新闻还是二次转载；
- 证据是否能够定位到论文页码、段落、图表或专利权利要求；
- 结论来自模型直接预测，还是由外部证据与模型结果共同推导。

Chukonu 的 evidence、provenance、locator 和 quality 结构可以承载这些信息，把“模型认为可能成立”转换为“预测及其证据上下文”。这不会让预测自动变成事实，但可以显著提高结果的可解释性和可审查性。

### 3.3 主动寻找反证，降低确认偏误

药物研发中的高成本错误，往往不是完全没有证据，而是团队只看到了支持项目继续推进的证据。Chukonu 的研究任务会针对关键陈述主动扩展“反例、争议、限制和 counter evidence”查询，并区分：

- 支持当前假设的证据；
- 与当前假设冲突的证据；
- 仅仅提及、但不能形成支持的证据；
- 证据不足、需要专家复核的结论。

这一能力可以用于：

- 靶点验证中的失败机制和组织差异检索；
- 蛋白质优化中的稳定性、活性、免疫原性权衡；
- 细胞扰动预测中的跨细胞类型失效条件；
- 动物模型结果向人体外推时的限制；
- 候选分子相关的毒理、安全性和脱靶信号；
- 项目立项前的专利阻断和同路线竞争分析。

它为 xTrimo 的“推演能力”增加了一套知识侧的制衡机制。

### 3.4 把实验缺口转化为可执行的研究任务

Chukonu 不只是返回文档，还会形成覆盖矩阵和 gap，指出某个结论在哪些维度上尚未得到满足，例如：

- 缺少原始论文或独立来源；
- 缺少特定物种、组织、细胞类型或疾病亚型证据；
- 缺少长期稳定性、剂量关系或安全性数据；
- 缺少专利地域、同族或权利要求层面的覆盖；
- 只有摘要，缺少可定位的全文证据；
- 存在相互冲突的研究结果。

接入实验系统后，这些知识缺口可以进一步映射为实验需求。联合系统就能从“搜到什么”前进到“下一步应该验证什么”。

需要注意：Chukonu 当前的 `information_gain_saturated` 表示一轮检索没有增加新的独立文档，并不等于基于模型不确定性计算出的最优实验。要支持真正的主动学习，还需要引入预测不确定性、实验成本、样本可得性和预期信息增益模型。

### 3.5 为专利与竞争情报建立连续监测能力

百图的基础模型和实验平台解决“能否发现、设计和验证”的问题，Chukonu 可以补充“是否具有新颖性、竞争环境如何、商业边界在哪里”的信息。

可提供的能力包括：

- 靶点、机制、序列、结构和适应症的专利检索；
- 申请人、发明人、IPC/CPC 和专利同族归并；
- 论文与专利证据的联合分析；
- 技术路线、竞争机构和公开时间线梳理；
- 关键陈述的支持、冲突与缺口标注；
- 按地域和时间范围保存检索边界。

Chukonu 可以支持技术和专利景观研究，但不能替代律师出具的自由实施分析或法律意见。专利状态、权利要求解释和侵权判断仍需专业人员确认。

### 3.6 提供可复现、可审计的研发决策记录

药物研发周期长，人员、模型和数据版本都会变化。未来回看一项决策时，仅保留最终报告通常不足以回答“当时为什么这样判断”。

Chukonu 当前已经具备以下审计基础：

- 不可变的搜索证据种子及哈希；
- 查询原文、有效查询和多轮查询轨迹；
- 来源快照、检索时间和候选预算；
- 每条证据的来源、版本、转换过程和稳定定位；
- 关键陈述与支持、冲突证据之间的对应关系；
- 证据覆盖、独立性、可定位性和质量评估；
- 任务停止原因及仍未解决的 gap。

如果进一步记录 xTrimo 模型版本、输入数据版本、预测任务 ID、实验批次和原始结果哈希，就可以形成贯穿“知识—模型—实验—决策”的证据链。这对内部复盘、合作交付、质量管理和受监管场景都具有长期价值。

## 4. 建议的联合架构

```text
                         ┌──────────────────────────┐
                         │  药物研发人员 / Agent    │
                         └────────────┬─────────────┘
                                      │ 目标、假设、约束
                         ┌────────────▼─────────────┐
                         │ Chukonu 知识与证据控制平面 │
                         │                          │
                         │ 规划 / 检索 / 反证 / 核验 │
                         │ 覆盖 / 溯源 / 研究状态    │
                         └───────┬──────────┬───────┘
                                 │          │
                    外部知识与证据│          │模型任务与结果
                                 │          │
              ┌──────────────────▼──┐   ┌───▼────────────────┐
              │ 论文 / 专利 / 网页   │   │ xTrimo 生物计算内核 │
              │ 领域数据库 / 监管数据│   │ 表征 / 预测 / 设计   │
              └─────────────────────┘   └───┬────────────────┘
                                             │候选与实验建议
                                      ┌──────▼───────────────┐
                                      │ 高通量实验与智能设备  │
                                      │ 采集 / 验证 / 提前终止 │
                                      └──────┬───────────────┘
                                             │实验结果
                         ┌───────────────────┴──────────────────┐
                         │                                      │
               回流 xTrimo 训练数据                    回流 Chukonu 证据账本
               形成模型数据飞轮                        形成决策与审计闭环
```

该架构中，Chukonu 不复制 xTrimo 的训练数据，也不侵入模型内部实现。双方通过稳定任务和证据契约连接：

- Chukonu 向 xTrimo 传递研究目标、约束、已知证据和待验证 gap；
- xTrimo 返回结构化预测、候选物、模型版本、不确定性及任务 artifact；
- 实验平台返回实验协议、样本、批次、条件、结果和质量控制信息；
- Chukonu 将预测和实验结果关联到具体 claim，更新证据覆盖和下一步行动建议。

## 5. 优先应用场景

### 5.1 靶点验证

**输入**：疾病、靶点、拟验证机制和适应症范围。

**Chukonu 贡献**：

- 汇总机制、遗传学、表达、动物模型和临床相关证据；
- 主动寻找失败研究和相反机制；
- 区分原始论文、综述、二次信息和不可定位内容；
- 建立竞争管线和专利布局；
- 输出待由 xTrimo 或湿实验解决的关键 gap。

**联合结果**：形成“公开证据 + xTrimo 推演 + 实验建议”的靶点决策 dossier。

### 5.2 蛋白质设计与优化

**输入**：目标功能及稳定性、活性、选择性、可制造性等约束。

**Chukonu 贡献**：

- 检索已知结构、功能位点、工程策略和失败案例；
- 搜索相似序列、已公开专利和工程化路线；
- 为 xTrimo 设计候选提供约束和先验背景；
- 在实验后关联设计依据、候选版本与 assay 结果。

**联合结果**：不仅保留“哪个候选更好”，还保留候选产生、筛选和淘汰的证据链。

### 5.3 虚拟细胞与基因扰动预测

**输入**：基因扰动、目标细胞类型、预期表型或转录组变化。

**Chukonu 贡献**：

- 检索同基因、同通路和相近细胞类型的已知研究；
- 标出跨物种、跨细胞类型外推的证据边界；
- 发现训练集之外的冲突结果和实验条件差异；
- 将预测结果转化为需要验证的明确 claim。

**联合结果**：把模型泛化能力与可解释的外部证据边界同时呈现给研发人员。

### 5.4 技术路线与专利景观

**输入**：技术方向、候选机制、重点机构和目标地域。

**Chukonu 贡献**：

- 联合检索论文和专利；
- 按专利同族、申请人、时间、IPC/CPC 和地域组织结果；
- 识别高密度布局、潜在空白和证据不足的判断；
- 保存检索边界和来源快照，支持后续增量更新。

**联合结果**：为研发优先级、合作对象和知识产权策略提供结构化输入。

## 6. 当前可直接复用的能力

以下能力无需改变 Chukonu 的核心架构即可用于第一阶段合作：

| 现有能力 | 对百图体系的直接价值 |
|---|---|
| 网页、论文、专利自动路由 | 为不同研发问题选择合适的外部知识源 |
| 多来源并发召回与独立降级 | 单一来源故障时仍保留可用证据 |
| 分领域重排 | 分别处理网页、学术和专利的质量特征 |
| PDF 深读 | 从摘要发现推进到可定位的论文正文证据 |
| 反证检索 | 减少只搜索支持性资料造成的确认偏误 |
| Claim 核验 | 将研发结论与支持、冲突和提及证据关联 |
| Coverage gap | 明确还缺什么资料或验证 |
| 不可变 research seed | 固定一次研究的输入证据和边界 |
| 持久化任务与幂等控制 | 支持长时间、多轮和可恢复的研究流程 |
| REST 与 MCP 接口 | 便于接入研发平台、Agent 和内部工作台 |

相关实现依据：

- [`SearchEngine`](../src/engine.py) 公开 `search` 与持久化 `research` 生命周期。
- [`DiscoveryService`](../src/application/discovery_service.py) 组织查询规划、召回和重排。
- [`ResearchService`](../src/application/research_service.py) 执行反证、多轮扩展、PDF 深读、核验和覆盖分析。
- [`Evidence`](../src/domain/evidence.py) 定义来源、定位、质量和检索边界。
- [`ResearchDossier`](../src/domain/research.py) 定义 finding、assessment、coverage、query trace 和停止原因。
- [`MCP Server`](../src/mcp_server.py) 为 Agent 暴露稳定工具接口。

## 7. 为生命科学场景需要补齐的能力

### 7.1 领域数据连接器

现有网页、OpenAlex 和专利数据需要扩展到更接近研发对象的来源，例如：

- PubMed、Europe PMC 等生物医学文献；
- ClinicalTrials.gov、药物和监管公开数据；
- UniProt、PDB、AlphaFold DB 等蛋白质与结构数据；
- ChEMBL、BindingDB 等分子和活性数据；
- GEO、SRA、CELLxGENE 等组学和细胞数据；
- 企业内部知识库、实验记录和经过授权的产业数据。

每个数据源都应保留许可、版本、更新时间、字段来源和质量限制，不能只转成一段无来源文本。

### 7.2 生物与实验对象模型

需要在通用 `Evidence` 之外增加领域结构，至少覆盖：

- 基因、蛋白、转录本、变体及稳定数据库 ID；
- 分子、结构、序列和版本；
- 物种、组织、细胞类型、细胞系和疾病亚型；
- assay 类型、实验协议、样本、批次、单位和条件；
- 仪器、软件、分析流程和质量控制；
- 模型名称、版本、输入、预测、不确定性和 artifact；
- 实验原始数据位置、哈希、结果及复核状态。

### 7.3 xTrimo 任务适配器

建议通过独立 port/adapter 接入 xTrimo，而不是把领域调用写入搜索服务。适配器应支持：

- 提交预测或设计任务；
- 查询任务状态、取消和幂等重试；
- 返回模型、数据和参数版本；
- 返回结构化候选、置信信息和 artifact；
- 声明输入输出模态及适用边界；
- 对敏感数据实施访问控制和审计。

### 7.4 实验任务与事件接口

为了形成真正的干湿闭环，需要把实验平台视为可观察、可控制的外部系统：

- 创建实验计划和批次；
- 接收设备采集事件和阶段结果；
- 记录提前终止及其触发依据；
- 关联样本、耗材、协议和仪器版本；
- 将结果回写到 claim、候选和模型任务；
- 区分原始结果、自动分析结果和人工确认结果。

### 7.5 主动学习与实验优先级

未来的实验调度不能只依据文档数量。应综合：

- xTrimo 的预测不确定性；
- 当前证据冲突程度；
- 实验预期信息增益；
- 实验成本、时间、失败率和样本可得性；
- 项目价值、专利风险和安全风险；
- 是否存在更便宜的替代验证路径。

Chukonu 可以承载这些决策输入和审计结果，但实验价值函数需要由百图的生物模型、实验专家和业务策略共同定义。

## 8. 分阶段落地建议

### 阶段一：外部证据 Sidecar

目标是低耦合验证实际价值，不改动 xTrimo 内核和实验系统。

- 选取靶点验证或蛋白质优化作为单一试点场景；
- 用 Chukonu 自动生成论文、专利、竞争和反证 dossier；
- 允许人工导入 xTrimo 输出摘要或 artifact 引用；
- 对比现有人工调研流程的时间、覆盖和反证发现情况；
- 建立双方首版实体、任务和证据 ID 映射。

阶段产物是可独立审阅的“知识证据包”，不是自动化药物研发结论。

### 阶段二：领域数据与模型任务集成

- 增加关键生命科学数据库连接器；
- 引入 BioEvidence 和 ExperimentEvidence；
- 建立 xTrimo 任务 adapter；
- 将模型预测自动转成待核验 claim；
- 在同一 dossier 中呈现外部证据、模型预测和适用边界。

阶段产物是“证据增强的模型推演工作台”。

### 阶段三：实验闭环

- 接入实验计划、批次和结果事件；
- 让 coverage gap 能够生成候选实验需求；
- 将实验结果关联到模型预测和外部证据；
- 使用不确定性、成本和信息增益进行实验排序；
- 建立提前终止、人工审批和异常处理机制。

阶段产物是“知识—模型—实验”的联合任务闭环。

### 阶段四：生产治理与规模化

- 建立租户、项目和敏感数据隔离；
- 固化模型、数据、实验和决策版本；
- 引入电子签名、审批和人工复核；
- 对关键任务建立质量门禁、回归评测和漂移监控；
- 根据适用场景评估 GxP、数据跨境、隐私和知识产权要求。

阶段产物是可被机构用户稳定使用和审计的研发基础设施。

## 9. 价值衡量指标

合作效果不宜只用搜索数量或模型准确率衡量。建议先建立基线，再比较以下指标：

### 9.1 知识与证据质量

- 关键 claim 的证据覆盖率；
- 原始、一手、可定位证据比例；
- 独立来源数量和来源集中度；
- 主动发现的冲突或负面证据数量；
- 论文、专利、临床和实验维度的缺口数量；
- 专家复核后被确认有效的证据比例。

### 9.2 研发效率

- 从问题提出到形成可评审 dossier 的时间；
- 文献和专利人工筛选时间；
- 从模型预测到实验决策的时间；
- 因提前发现反证、重复路线或专利风险而避免的实验；
- 单位有效结论所需的实验数量、成本和周期；
- 实验数据回流后模型或候选排序的改善。

### 9.3 可追溯性与治理

- 能够完整还原数据、模型、证据和实验版本的决策比例；
- 具有稳定 locator 和原始数据哈希的关键结论比例；
- 未记录来源、版本或转换过程的 artifact 数量；
- 人工复核、审批和例外处理的闭环率；
- 重复执行同一研究任务时的可复现程度。

## 10. 风险与非目标

### 10.1 Chukonu 不是事实真值机

检索相关性不等于事实置信度，论文发表也不等于结论已被重复验证。Chukonu 能揭示证据和缺口，不能自动消除生命科学本身的不确定性。

### 10.2 文档证据不能替代实验

对模型预测最关键的验证仍来自设计合理、质量受控的实验。外部知识可以降低搜索空间和发现风险，但不能把未经实验验证的候选包装成已证实结果。

### 10.3 通用模型分数不能解释为生物学概率

当前重排和陈述核验使用通用语言模型或规则，其输出不能作为活性、稳定性、毒性或临床成功率。联合系统必须严格区分检索分数、文本核验置信度、xTrimo 预测不确定性和实验统计结果。

### 10.4 自动化不能绕过专家责任

关键靶点、候选推进、实验终止、专利判断和受监管决策仍需对应领域专家审批。系统应保留 `needs_expert_review`，而不是为了流程自动闭环强行给出确定结论。

### 10.5 数据权利与隐私必须前置

公共数据库、论文全文、产业脱敏数据和实验数据具有不同的许可及使用边界。检索、模型调用、持久化和跨机构共享必须遵守各自授权，受限数据不得未经批准发送给外部模型。

## 11. 建议的产品表达

不建议把 Chukonu 对外描述为另一套“AI 制药操作系统”，这会模糊它与 xTrimo、数据平台及实验设备的边界。

建议采用以下定位：

> **Chukonu 是生命科学 AI 操作系统的知识与证据控制平面。它连接外部研究、模型推演和实验结果，让每项研发结论都有来源、有反证、有边界，并能转化为下一步行动。**

更简洁的联合表达是：

> **xTrimo 负责推演生命，实验室负责询问生命，Chukonu 负责确认系统知道了什么、依据是什么、还缺什么。**
